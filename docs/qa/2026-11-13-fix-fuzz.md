# Fix and fuzz: Android device QA, 2026-11-13

## Scope and isolation

Based on app-v1 `3b20bc371f230d1aa527a055c45638fb560023de`, including merged charge-schedule and calendar changes. Original checkout and installed production application retained. All edits are on local branch `jarvis/device-fix-fuzz-20261113`; not pushed, merged or published.

Physical target: OnePlus 13 CPH2655, Android 16 over authorized USB. Debug app has separate `.qa` application ID and “IONIQ 6 QA” label. QA entrypoint uses in-memory demo settings, no PlatformBridge or auto-updater, and refuses HTTP socket creation. No real vehicle commands, credentials, calendar permissions, calls or app-data clearing were exercised.

## Reproduced defects and fixes

- Non-finite telemetry crashed rounding; malformed numeric/location/image attributes are now rejected/tolerated, and unknown binary states remain unknown.
- Charge-limit acknowledgement now requires both AC and DC targets; history/statistics honor discovered entity IDs.
- Hold-to-confirm now cancels when pointer leaves or control becomes disabled.
- Home, charging and valet content now wraps; short/large-text control screens remain scrollable.
- Charge schedule rejects malformed time and invalid minute values; round-trip/deep-copy fuzz protects payload preservation.
- Long schedule departure values and keyboard-visible OTP dialog no longer overflow.
- Dismissed sign-in cannot send an OTP when a pending response arrives; disposed schedule sheet cannot update after picker return.

## Verification

- Deterministic input fuzz: 256 attribute cases, 4,320 schedule minute/mode round trips, 96 deep-copy cases.
- Route layout matrix: 12 routes × 3 viewports × 2 text scales = 72 cases, plus 14 modal/interruption cases.
- Regular Flutter tests: 167 passed. Static analyzer: no issues found.
- Home Assistant Python tests: 22 passed using cached/offline pytest, pillow and requests.
- Physical-device standalone harness: seed 6013, 3 shuffled passes across 11 routes, navigating out and back. Reports `QA_COMPLETE cycles=33 errors=0 demo=true` when successful. This is route/lifecycle stress, not random button injection or exhaustive native integration.
- Android debug APK builds successfully. Kotlin plugin/SDK XML tooling warnings remain.

## Limits and outstanding work

The full suite is NOT green: 14 screenshot golden tests mismatch, with 12 already failing before edits and two additional screenshot cases present after updating app-v1. Baselines were not regenerated to conceal drift. They need visual review on the agreed rendering environment.

Android instrumentation runner could not build because Google Maven DNS/dependency resolution failed, even after permitted retry. Its unexecuted candidate is retained as `tool/blocked-integration/device_fuzz_test.dart.txt`; integration_test is not added as an app dependency. A standalone offline device harness was used instead.

No live Bluelink, HA server, native calendar permission flow, camera capture, actual car commands, production credentials, release signing or production-app upgrade tested. This work does not establish safety of live charge scheduling on the vehicle.

Reproduce offline QA build: `flutter build apk --debug --no-pub -t tool/qa_main.dart --dart-define=QA_FUZZ=true`. The harness is opt-in; without QA_FUZZ the same entrypoint opens the isolated demo normally.
